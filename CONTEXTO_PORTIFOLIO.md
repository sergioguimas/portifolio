# Tom de comunicação

## Tom desejado

Profissional, direto, confiável e objetivo.

O texto deve transmitir maturidade sem parecer exagerado.

## Evitar

Evitar frases muito genéricas ou infladas, como:

* “especialista absoluto”;
* “soluções revolucionárias”;
* “alta performance” sem prova;
* “mercado global” sem contexto;
* métricas inventadas;
* resultados numéricos não informados;
* clientes, faturamento ou nomes sensíveis não autorizados.

## Preferir

Preferir frases concretas, como:

* “sistema multi-tenant para gestão de clínicas”;
* “automação de confirmações via WhatsApp”;
* “dashboard com filtros por período”;
* “modelagem com PostgreSQL e Supabase”;
* “integração com API externa”;
* “fluxo multi-etapas com validações condicionais”;
* “correções de fuso horário em relatórios”;
* “scripts para reduzir tarefas repetitivas”.

## 1. Eliza

### Nome

Eliza

### Categoria

SaaS / HealthTech / Gestão de clínicas

### Status sugerido

Em desenvolvimento / MVP funcional / Produção inicial

### Resumo curto

SaaS multi-tenant para clínicas, com agenda, pacientes, profissionais, configurações por organização, PWA e automações via WhatsApp.

### Descrição expandida

O Eliza é um sistema de gestão para clínicas e profissionais de saúde, criado para centralizar agenda, pacientes, serviços, profissionais e confirmações de atendimento em uma aplicação web multi-tenant.

O sistema foi pensado para pequenos negócios que precisam organizar atendimentos, reduzir falhas de comunicação e automatizar lembretes e confirmações via WhatsApp.

### Problema

Clínicas pequenas costumam depender de agendas manuais, conversas soltas no WhatsApp e processos pouco integrados para marcar, confirmar e cancelar atendimentos.

* Criação de agenda pública por organização.
* Integração com WhatsApp via Evolution API.
* Correções de fuso horário em agenda e lembretes.
* Ajustes de PWA e experiência mobile.
* Participação em decisões de produto, regra de negócio e roadmap.

### Stack

* Next.js
* React
* TypeScript
* Tailwind CSS
* Supabase
* PostgreSQL
* Row Level Security
* Evolution API
* WhatsApp
* Docker/VPS
* PWA

### Funcionalidades principais

* Organização multi-tenant.
* Agenda por profissional.
* Cadastro de serviços.
* Cadastro de pacientes/clientes.
* Página pública de agendamento.
* Confirmação e cancelamento por WhatsApp.
* Lembretes automáticos.
* Configurações por organização.
* Status de atendimento.
* PWA para uso em mobile.

### Desafios técnicos

* Isolamento de dados entre organizações.
* Regras de agenda com fuso horário.
* Integração com WhatsApp via instâncias externas.
* Diferença entre agendamento público e interno.
* Organização de status de atendimento.
* Fluxo de lembretes automáticos.
* Experiência responsiva para clínica e paciente.

### Resultado / aprendizado

## 2. Fidelidade

### Nome

Fidelidade

### Categoria

Sistema comercial / Gestão de clientes / Regras de negócio

### Status sugerido

Projeto real / Em evolução

### Resumo curto

Sistema de fidelidade para lojistas, com clientes, compras, itens, pontuação, descontos, dashboard e regras comerciais.

### Descrição expandida

O Fidelidade é um sistema voltado para lojistas acompanharem clientes, compras, pontuação e indicadores comerciais.

O projeto lida com regras de negócio mais detalhadas, como descontos por item, desconto total na nota, rateio proporcional, geração de pontos, filtros por período e dashboard de vendas.

### Problema

Negócios comerciais precisam acompanhar vendas, clientes recorrentes, pontuação e descontos de forma confiável.

Planilhas ou controles manuais dificultam a conferência de valores, a análise por período e a aplicação correta de regras de pontuação.

### Minha atuação

* Desenvolvimento de funcionalidades de vendas e clientes.
* Implementação de regras de desconto.
* Ajustes de dashboard e filtros.
* Correção de inconsistências em relatórios.
* Tratamento de fuso horário em datas de compra.
* Modelagem e uso de dados em Supabase/PostgreSQL.
* Apoio em análise de divergências entre relatório do cliente e sistema.

### Stack

* Next.js
* React
* TypeScript
* Supabase
* PostgreSQL
* Tailwind CSS
* API Routes

### Funcionalidades principais

* Cadastro de clientes.
* Registro de compras.
* Itens de compra.
* Valor unitário com precisão decimal.
* Desconto por produto.
* Desconto total na nota.
* Rateio proporcional de desconto.
* Geração de pontos.
* Dashboard com indicadores.
* Filtros por período.
* Paginação de vendas.
* Correção e normalização de datas.

### Desafios técnicos

* Regras financeiras com arredondamento.
* Desconto total proporcional entre itens.
* Evitar descontos maiores que o subtotal.
* Manter consistência entre compra e itens.
* Corrigir diferença entre data de lançamento e data real da venda.
* Tratar datas considerando o fuso America/Sao_Paulo.
* Conferir divergências entre relatório externo e banco de dados.

### Resultado / aprendizado

O projeto fortaleceu experiência com regras de negócio comerciais, consistência de dados, relatórios, dashboards e tratamento cuidadoso de datas e valores monetários.

## 3. Autoatendimento e-Útil

### Nome

Autoatendimento e-Útil

### Categoria

Frontend / UX / Integração com API

### Status sugerido

Projeto real / Integração em andamento

### Resumo curto

Página de agendamento para certificados digitais, com formulário multi-etapas, validações, regras condicionais e integração com backend em Go.

### Descrição expandida

O Autoatendimento e-Útil é uma página de solicitação e agendamento de certificados digitais, criada para simplificar o atendimento inicial de clientes.

O fluxo foi pensado para ser usado por um público amplo, incluindo usuários menos técnicos, com etapas claras, validações e preenchimentos automáticos sempre que possível.

### Problema

O processo de solicitação de certificados digitais pode envolver muitas informações, modalidades, tipos de certificado, dados pessoais, dados empresariais e regras específicas.

Um formulário longo e confuso poderia aumentar abandono e erros de preenchimento.

### Minha atuação

* Desenvolvimento frontend.
* Estruturação do fluxo multi-etapas.
* Organização visual e UX.
* Criação de campos condicionais.
* Integração planejada com backend em Go.
* Ajustes no fluxo SafeID.
* Discussão de payloads com backend.
* Adaptação para uso dentro do site WordPress existente.

### Stack

* React
* TypeScript
* Tailwind CSS
* Vite
* API REST
* Go/Golang no backend
* WordPress como ambiente de incorporação

### Funcionalidades principais

* Formulário em etapas.
* Escolha de finalidade, modalidade, categoria e tipo de certificado.
* Campos condicionais para pessoa física e jurídica.
* Validação de CPF/CNPJ.
* Consulta de CEP e cidade.
* Consulta de CNPJ.
* Seleção de dias e período de atendimento.
* Confirmação com resumo.
* Oferta SafeID pós-confirmação.
* Envio inicial por POST.
* Atualização posterior por PATCH.

### Desafios técnicos

* Criar uma experiência simples para um processo complexo.
* Evitar abandono do formulário.
* Trabalhar com regras condicionais sem confundir o usuário.
* Integrar frontend React com backend em Go.
* Adaptar a solução ao site WordPress sem redirecionar o usuário.
* Separar confirmação principal da oferta SafeID.

### Resultado / aprendizado

O projeto reforçou experiência com UX aplicada, formulários multi-etapas, integração frontend/backend, regras condicionais e preocupação com o comportamento real do usuário.

### Sugestão de título para card

Autoatendimento e-Útil — agendamento inteligente para certificados digitais

### Sugestão de descrição para card

# Cuidados importantes

## Não inventar informações

Não inventar:

* faturamento;
* número de usuários;
* clientes;
* métricas de produtividade;
* nomes de empresas clientes;
* links de demo inexistentes;
* repositórios privados;
* status de produção não confirmado.

## Tratar projetos privados com transparência

Quando um projeto não puder ter código aberto, usar termos como:

* “case privado”;
* “projeto interno”;
* “repositório privado”;
* “imagens demonstrativas”;
* “informações sensíveis omitidas”.

## Valorizar aprendizado e processo

Quando não houver métrica objetiva, destacar:

* desafio técnico;
* tomada de decisão;
* evolução do produto;
* integração realizada;
* regra de negócio implementada;
* problema operacional resolvido.
